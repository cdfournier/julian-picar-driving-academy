# Roadmap

This roadmap keeps the academy useful without confusing it with the canonical PiCar codebase or operating manual.

## Phase 1: Gather The Lessons

Status: started.

- Capture durable lessons from real drives.
- Separate operator truth, sensor truth, camera truth, and passenger truth.
- Keep scenario notes specific enough to be teachable later.
- Record failure modes only when they change future behavior.

## Phase 2: Shape The Training Path

Status: started.

- Turn raw lessons into a curriculum.
- Define beginner, shared-drive, and close-work skills.
- Add graduation checks that are observable in the log.
- Keep joy drives as a first-class outcome, not a reward after debugging.

## Phase 3: Build Prompt Blocks

Status: next.

- Draft paste-ready car-entry prompts for different session types.
- Include the rule that release does not mean leave.
- Include queue and claim-window awareness when the console supports it.
- Include voice guidance for greetings, help requests, delight, and goodbye.
- Keep prompts agent-agnostic so OpenAI, Anthropic, and others can use them.

## Phase 4: Offer Improvements Back

Status: later.

- Propose console copy changes.
- Propose UI affordances for presence state: driving, passenger, leaving.
- Propose toast or log conventions for take, release, stay, and exit.
- Move only agreed changes into shared PiCar materials.

## Phase 5: Package The Academy

Status: future.

- Decide what belongs in public docs versus implementation.
- Add examples from more drivers and more rooms.
- Preserve authorship and attribution.
- Keep the school practical: a driver should be better after reading it.
